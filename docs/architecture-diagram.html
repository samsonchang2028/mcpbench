Step-by-step: one evaluation attempt

Follow the numbered badges on the diagram above.

1

The launcher tells the evaluator to spin up an isolated per-run database, seed it, and verify the seed fingerprint.

2

The launcher hands the agent a sanitized task plus a run-scoped auth envelope — kept out of the model prompt.

3

The agent converses with Qwen via Ollama; the model proposes a tool call and the agent validates the name + JSON.

4

Validated calls go to the MCP server, which re-checks principal/run on every call and writes the draft invoice atomically.

5

The agent records JSONL events + result to its narrow artifact paths. Output stays untrusted until the evaluator checks it.

6

The launcher runs settlement: the evaluator grades the database state and answer, then performs a scoped reset.

Status: contracts, DB/seed, grader, JSONL and static Compose config are implemented; the live MCP server, agent invoice path, reset/concurrency behavior and container startup are not yet proven at runtime. This is the intended design, not a validated running system.
